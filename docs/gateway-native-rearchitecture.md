# PixelPlayer → dedicated XPS gateway client

## Context

PixelPlayer started as a generic local-file Android music player, then grew "linked account" support for eight parallel content sources bolted on alongside local MediaStore files: Telegram, Google Drive, NetEase Music, QQ Music, Jellyfin, Plex, and our own Navidrome/Subsonic-protocol gateway. Tonight's gateway-stats work kept hitting friction that traces back to this architecture — the app treats our gateway as just one optional provider among many, defaults to local-file assumptions in the player/session layer, and requires the user to type a server URL by hand like it might be anyone's Subsonic server.

The decision: PixelPlayer stops being a generic multi-source player and becomes a dedicated client for **our** gateway — same relationship the Spotify or YouTube Music apps have with their one backend. Concretely:
- Delete Telegram, Google Drive, NetEase, QQ Music, Jellyfin, Plex, and Roku support entirely — not hidden, removed.
- Delete local on-device (MediaStore) music scanning/playback/editing entirely.
- The gateway (`api.tinotenda.co`) comes pre-configured — no free-text server URL field.
- Chromecast, Wear OS, and Android Auto stay (they're already source-agnostic presentation surfaces for whatever the unified library contains).
- Offline downloads of *gateway* content stay (`NavidromeDownloadManager` — distinct from local-file concerns; downloaded files use `file://` URIs, which must **not** be removed even though `content://` MediaStore URIs are).

**This is already partially underway.** Prior work left comments like *"Local media browsing is retired... the library is served by the XPS gateway"* in `SetupScreen.kt`, `SetupViewModel.kt`, `PlayerViewModel.kt`, and `AndroidManifest.xml` (storage permissions already dropped, the Folders tab already hidden). This plan finishes that direction properly instead of leaving it half-done, and extends the same treatment to the other six services.

## Explicit scope decisions (made without asking, stated here so they're checkable)

- **Offline gateway downloads stay.** `NavidromeDownloadManager`, its Room table, and the `file://` playback path it uses are gateway functionality, not "local music" — untouched.
- **Chromecast/Wear/Auto stay, unmodified in structure.** All three are already fully source-agnostic (confirmed zero references to any of the seven removed services in `CastStateHolder.kt`, `CastSyncCoordinator.kt`, `AutoMediaBrowseTree.kt`, or the entire `wear/` module) — they'll just naturally reflect a smaller library once the sources feeding it shrink. Plex Companion/Connect/Roku — which *are* cast-adjacent — go with Plex.
- **DB schema:** old Room migrations for removed features' tables are *left in place* (standard Room practice — existing installs must still walk through migration history) rather than rewritten; a new migration is added at the end to `DROP TABLE` the now-orphaned tables and remove the entities from `@Database(entities=[...])`. This is a data-cleanup step, not a compile requirement, so it's sequenced last.
- **Backup/restore mechanism stays** (playlists/favorites/settings restore is still useful); the module handlers for removed sources become no-ops rather than being preserved for back-compat.
- **App name/package rename is explicitly out of scope.** "PixelPlayer" is a one-line string resource if ever wanted later; the package/applicationId (`com.theveloper.pixelplay`) is a much larger, separate, optional mechanical rename. Not part of this plan.
- **Gateway login moves into onboarding.** Today `SetupScreen`'s pager finishes with zero forced account-linking — gateway sign-in only happens later, opportunistically, via Settings → Accounts or the "Cloud Streaming" sheet. For a dedicated single-service app, sign-in belongs in first-run, Spotify/YTM-style. Server URL is baked in as a constant; onboarding only asks for username + password.
- **The multi-provider "Accounts"/"Cloud Streaming" abstraction collapses to one gateway identity.** No more `ExternalServiceAccount` enum of 7 services — just "signed in as `<user>` / Sign out."
